# Fulfillment FBO/FBW: Excel, ШК коробов WB, экспорт и печать

Актуально на 24.09.2026. Это канонический документ по связи физических коробов ELESTET с пустыми коробами поставки WB. Старое правило о сортировке ШК из WB API по числовому суффиксу отменено.

## Граница моделей и источники истины

- Здесь рассматривается только FBO/FBW-поставка. FBS-поставка `WB-GI-…` является другой сущностью и не участвует в этой нумерации.
- Поставка WB в начале считается пустой: ELESTET не получает из неё состав коробов. Состав, количества и распределение товаров ведутся в ELESTET и затем выгружаются в WB.
- Содержимое физического короба и его номер определяет ELESTET.
- Системный ШК физического короба определяет ELESTET и хранит независимо от WB.
- Два ШК WB создаются на стороне WB пустыми. До официального ответа поддержки WB временным эталоном их порядка является однолистный Excel, скачанный из интерфейса WB.
- Порядок массива упаковок WB API не является доказанной идентичностью короба. API не имеет права назначать или переставлять ШК WB между коробами ELESTET.
- API продолжает синхронизировать безопасные сведения поставки: числовой ID FBO, склад, плановую дату, тип груза, статус, количества и условия приёмки. Синхронизация этих сведений не трогает пары ШК WB.

## Три идентификатора одного физического короба

1. `fulfillment_boxes.barcode` — системный ШК вида `EL_C{company}_P{batch}_S{supply}_B{box}`. Он детерминирован аккаунтом, партией, поставкой и номером короба.
2. `fulfillment_boxes.wb_barcode` — значение колонки WB `ШК короба`.
3. `fulfillment_boxes.wb_external_barcode` — значение колонки WB `ШК короба для печати в стороннем сервисе`.

Оба WB-кода составляют одну неразделимую пару. Нельзя принять строку, в которой заполнен только один код. Печатный PDF в WB-режиме использует `wb_external_barcode`; обычный `wb_barcode` сохраняется для шаблона WB и отображения связи.

## Постоянная связь номера короба

- `fulfillment_box_barcode_registry` сохраняет системный номер/ШК. Удаление короба не освобождает номер как новую идентичность; повторное создание того же номера возвращает тот же системный ШК.
- `fulfillment_wb_box_code_registry` хранит проверенную Excel-пару по ключу `supply_id + box_number`, а не по временному UUID строки короба.
- Если короб удалили после загрузки WB Excel, запись пары WB остаётся. Когда в той же поставке снова создаётся этот номер короба, триггер автоматически возвращает оба WB ШК.
- Замена числового `wb_supply_id` означает другую поставку WB. Она атомарно очищает старый WB registry, оба WB-кода коробов и связанные кэшированные метаданные. Системные ШК, содержимое и КИЗ при этом не меняются.
- Прямое одиночное изменение WB-кода запрещено. Полная пара меняется только атомарной Excel-загрузкой всей поставки.

## Импорт WB ШК из Excel

Файл принимается без ручного удаления колонок или переименования заголовков.

- Допустим только `.xlsx` или `.xls` размером до 20 МБ.
- В книге должен быть ровно один лист. Несколько листов являются ошибкой, даже если нужные колонки найдены только на одном.
- Система ищет одну строку заголовков в любом месте листа. Основные точные заголовки: `ШК короба` и `ШК короба для печати в стороннем сервисе`; сохранены совместимые прежние варианты `ШК ВБ` и `ШК ВБ для других сервисов`.
- Любые остальные колонки и их порядок игнорируются. Поэтому принимаются исходный WB-шаблон, файл только с двумя нужными колонками и будущий гибридный отчёт.
- Полностью пустая строка игнорируется и не занимает номер короба.
- Первая заполненная пара после заголовка получает `box_number=1`, вторая — `2` и далее. Номер физической строки Excel не является номером короба.
- Формулы и Excel-ошибки в двух кодовых колонках запрещены. Коды читаются как отображаемый текст без числового преобразования.
- Пустая половина пары, повтор обычного кода, повтор печатного кода, дубли заголовков или несколько возможных строк заголовков блокируют весь импорт.

После чтения строится предпросмотр `Сейчас → Станет` на одном уровне. Сервер принимает файл только если набор получившихся номеров **точно равен** текущему набору коробов поставки:

- строка Excel для отсутствующего короба показывается красным;
- короб ELESTET без пары из файла показывается оранжевым;
- при любом расхождении финальная кнопка недоступна, частичная запись запрещена;
- существующие пары показываются как замена;
- полностью совпадающий файл показывает `Эти ШК уже привязаны` и не переписывает registry.

Финальное подтверждение существует всегда: и при первой привязке, и при замене. Дополнительной модалки до загрузки файла нет.

## Импорт содержимого коробов

Это отдельное действие и отдельный формат: `Баркод`, `Количество`, `Номер короба`.

- Баркод содержит ровно 13 цифр; количество и номер короба — положительные целые числа.
- Пустые строки игнорируются. Повторы одного баркода внутри одного короба суммируются.
- Строка только с номером создаёт отсутствующий пустой короб, но не очищает уже существующий короб.
- Если для указанного существующего короба есть товарные строки, его содержимое полностью заменяется. Короба, отсутствующие в файле, остаются без изменений.
- До применения UI показывает точное действие по каждому коробу: создать пустым, создать и заполнить, заполнить впервые, заменить или оставить без изменений.
- Активные КИЗ заменяемого содержимого не удаляются бесследно: они переводятся в историю с причиной Excel-замены. Повторный скан связывает КИЗ с новым товаром/коробом без повторного увеличения уже импортированного количества.
- Замена блокируется, если товар короба участвует в активной FBS-привязке `reserved/awaiting_wb`.
- Сервер выполняет замену атомарно; частично применённого файла быть не должно.

## Единое окно «Действия с Excel»

Зелёная Excel-иконка поставки открывает одну модалку высотой `90vh` с тремя вкладками:

1. `Содержимое коробов` — скачать трёхколоночный шаблон, загрузить и применить заполненное содержимое.
2. `Загрузить WB ШК` — загрузить однолистный файл WB, проверить пары и подтвердить привязку/замену.
3. `Экспорт` — сформировать готовый системный или WB-файл из текущих данных ELESTET.

Шапка и нижняя панель закреплены; прокручивается только центральная область. Это также подчиняется общему правилу модалок из `memory-bank/systemPatterns.md`.

## Экспорт из ELESTET

### Системный ШК короба

- Доступны режимы `По коробам`, `По баркодам`, `Оба`.
- `Оба` создаёт один XLSX: первый лист `По баркодам`, второй `По коробам`.
- В коробном режиме обязательны `Баркод товара`, `Кол-во товаров`, `Системный ШК короба`, `Срок годности`, `Номер короба`.
- Дополнительные колонки: `Артикул ВБ`, `Артикул продавца`, `Название товара`, `Цвет`, `Размер`. Выбор хранится локально в браузере.

### ШК короба WB

- Вариант остаётся видимым, но недоступен с подписью `Отсутствует`, пока хотя бы у одного короба нет полной пары WB.
- Доступен только готовый режим `По коробам`; `По баркодам` и `Оба` остаются на месте, но недоступны с подсказкой `Доступно для системных ШК`.
- Дополнительные колонки исчезают. Формируется ровно однолистный WB-шаблон из пяти колонок:
  `Баркод товара`, `Кол-во товаров`, `ШК короба`, `Срок годности`, `ШК короба для печати в стороннем сервисе`.
- Для пустого короба создаётся строка с пустым товарным баркодом и количеством `0`, но с обоими WB ШК.
- Экспорт использует только пары, сохранённые проверенным Excel-импортом. `trip_lines.wb_package_codes` остаётся совместимым зеркалом и не является источником сопоставления.

## PDF и синхронизация WB

- В окне `ШК коробов` пользователь выбирает `Системный ШК` или `ШК WB`; WB-вкладка недоступна, пока не заполнены все пары выбранной области.
- На уровне отдельного короба разрешена только печать уже связанного кода. Ручного назначения WB ШК одному коробу нет.
- На уровне поставки можно сохранить числовой FBO ID WB и выполнить `Синхронизировать с WB`. Этот синк получает склад, дату, тип и другие метаданные, но не загружает и не назначает ШК коробов.
- Получение/печать package codes через WB API отключено. Серверный `package_info` безопасно отказывает и направляет к Excel.
- Системные и WB PDF доступны на уровнях короба, поставки, партии и связанной строки Логистики по уже сохранённым данным.

## История Excel и права — подготовлено локально, ещё не production

Коммит `b86d7c9` подготовил, но пока не опубликовал:

- append-only `fulfillment_excel_action_history` для успешных изменяющих загрузок содержимого и WB ШК;
- пользователь, дата, исходное имя файла, результат `applied/unchanged`, точные снимки `до/после`;
- последние 100 событий в UI; тяжёлые подробности загружаются только при раскрытии записи;
- одинаковая повторная WB-загрузка записывается как `Без изменений`, но mappings не переписываются;
- скачивания Excel не журналируются; кнопки отката/восстановления прошлой версии нет;
- серверная проверка `fulfillment_manage`, включая фактического исполнителя pipeline-стадии;
- запрет прямой записи в registry и отключение старых обходных mutating RPC для `authenticated`.

До применения `supabase/patch_fulfillment_excel_action_history.sql` и публикации соответствующего frontend эта история и усиленная серверная проверка не считаются production-функцией. Frontend нельзя выпускать раньше миграции, потому что он вызывает новые RPC.
