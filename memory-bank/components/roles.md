# Роли и назначения сотрудников

## Модель

- `roles` — переиспользуемые шаблоны разрешений внутри компании. Роль не обязана иметь сотрудников.
- `role_assignments` — связь many-to-many между ролью и пользователем.
- Одна роль назначается нескольким сотрудникам; один сотрудник технически может иметь несколько ролей.
- Если у сотрудника несколько ролей, `useMyPermissions` объединяет разрешения по OR.

## Сохранение

- Фронтенд создаёт/обновляет саму роль отдельно.
- RPC `set_role_assignments(role_id, user_ids[])` атомарно приводит назначения роли к переданному списку.
- Триггер назначения добавляет пользователя в `account_members` как `viewer`, не понижая существующую системную роль.
- При снятии последнего назначения удаляется только автоматически добавленное членство `viewer`; owner/admin/manager/operator не затрагиваются.

## Интерфейс

- В новой роли сотрудник необязателен.
- В редактировании отображаются все назначенные сотрудники.
- Добавление выполняется по email, UUID или короткому ID `U{n}`; можно последовательно добавить несколько человек.
- Карточка роли показывает количество и плашки назначенных сотрудников.

## Миграция

- SQL: `supabase/patch_role_assignments.sql`.
- Legacy-значения `roles.assigned_user_id` сначала копируются в новую таблицу, затем старая колонка и старый триггер удаляются.
- Миграция применена в production 26.08.2026: 2 роли, 2 перенесённых назначения.
