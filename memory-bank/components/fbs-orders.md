# FBS Orders — актуальная архитектура (09.08.2026)

## Файлы
- UI: `src/pages/FbsOrdersPage.tsx`
- Backend proxy/sync: `supabase/functions/wb-fbs/index.ts`
- Cache: `fbs_orders`, `fbs_sync_log`
- Product source: `products`
- Warehouse source: `wms_warehouses`, `wms_cell_items`

## Загрузка
1. Выбранный магазин хранится в localStorage.
2. Страница сразу читает `fbs_orders` из Supabase.
3. «Обновить» вызывает `sync_orders`, затем перечитывает DB и открытые WB-поставки.
4. `get_supplies(closed=false)` нужен, чтобы показывать даже пустые поставки.

## Табы
- `pending` → Новые.
- `assembling` → На сборке.
- `delivering` → В доставке.
- `done` → Отгружено; текущая done-пометка дополнительно хранится локально.

## «На сборке»
- Map родителей создаётся сначала из всех открытых WB-поставок.
- Затем заказы раскладываются по `supply_id`; отсутствующая связь попадает в `__none__`.
- Родитель раскрывается аккордеоном; при сворачивании его выбранные заказы снимаются.
- Родительская одиночная стрелка запускает передачу всех заказов поставки в доставку.
- Дочерние действия: две встречные стрелки для переноса, принтер для WB-стикера.
- Массовая панель: счётчик, печать, перенос, лист подбора, закрытие/сброс.

## Создание и перенос
- Модалка имеет `mode: assemble | move` и табы создания/существующей поставки.
- В режиме move исходные supply ID исключаются.
- Новая поставка создаётся `create_supply`; каждый заказ добавляется через `add_order_to_supply`.
- Частичные ошибки не скрываются: успешные строки обновляются, failed IDs показываются пользователю.
- Default name: `Название магазина ДД.ММ.ГГГГ`.

## Данные товара
- WB FBS order — источник `order id`, `nmId`, `chrtId`, `skus`.
- `fbsOrderBarcode()` выбирает точный SKU/баркод заказа.
- `products` находится по выбранному `store_id` и `nm_id`.
- `productSizeByBarcode()` ищет `sizes[].skus` и учитывает `chrtId`; результат — `techSize`.
- Фото: первая доступная `photos[].c246x328`/`big`.
- Нет точного варианта → размер `null`, в UI красное «Размер не определён»; случайный размер запрещён.

## Печать и лист подбора
- `get_sticker` вызывается батчами максимум по 100 order IDs.
- Одиночная и массовая печать используют один handler.
- Picking list строится из выбранных заказов одной поставки.
- PDF открывается через blob URL; XLSX скачивается.
- Поля: фото, бренд, наименование, размер, цвет, артикул продавца, WB-стикер, баркод.

## Передача в доставку
- Действие разрешено только на родителе поставки.
- Текущий `handleShip` уменьшает WMS-остаток найденной ячейки, пытается отправить stock на WB и переводит строки UI в `delivering`.
- Не добавлять передачу в доставку на отдельный заказ или в массовую панель без изменения бизнес-правила.

## UI-иконки
- Две встречные стрелки: перенос заказа между поставками.
- Одна стрелка вправо: передать всю поставку в доставку.
- Принтер: получить/напечатать WB-стикер.
