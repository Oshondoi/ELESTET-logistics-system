# FBS Orders — актуальная архитектура (11.08.2026)

## Файлы
- UI: `src/pages/FbsOrdersPage.tsx`
- Edge Function: `supabase/functions/wb-fbs/index.ts`
- Миграция/RPC: `supabase/patch_fbs_reliable_sync.sql`
- Кэш: `fbs_orders`, `fbs_sync_log`
- Товары: `products`
- WMS: `wms_warehouses`, `wms_cell_items`

## Надёжный снимок WB
1. UI сразу читает последний корректный снимок из `fbs_orders`.
2. `sync_orders` загружает `/api/v3/orders` за 30 дней постранично до точного `next=0` и объединяет результат с `/api/v3/orders/new`.
3. Для каждого уникального order ID запрашивается официальная пара статусов через `/api/v3/orders/status`, батчами максимум по 1000.
4. ID и cursor, которые WB описывает как int64, разбираются и передаются как точные строки, без JS-округления.
5. RPC `apply_fbs_sync_snapshot` проверяет количество заказов/статусов и применяет весь снимок одной транзакцией.
6. При сбое новый снимок не применяется. В `fbs_sync_log.error` записывается причина, а UI продолжает показывать последний успешный снимок и время его получения.
7. Одновременные sync одного магазина объединяются; более старый снимок не может перезаписать более новый.

## Поля БД
`fbs_orders`:
- `wb_order_id text`;
- `supplier_status text`;
- `wb_system_status text`;
- `status_synced_at timestamptz`;
- `is_in_latest_snapshot boolean`.

`fbs_sync_log`:
- `last_synced_at`;
- `orders_count`;
- `status_counts jsonb`;
- `snapshot_from`;
- `error`.

## Вкладки
- `pending` / «Новые»: `supplierStatus=new`, `wbStatus=waiting`.
- `assembling` / «На сборке»: `supplierStatus=confirm`, `wbStatus=waiting`.
- `delivering` / «В доставке»: `supplierStatus=complete`, пока `wbStatus` не финальный.
- `completed` / «Завершённые»: `sold`, `canceled_by_client`, `defect`.
- `cancelled` / «Отменённые»: `supplierStatus=cancel`, `declined_by_client`, `canceled`.
- `archive` / «Архив»: строка вне последнего 30-дневного снимка либо новая неизвестная комбинация, которую нельзя безопасно отнести к другой вкладке.

Наша система не отменяет заказы. Она только читает и отображает статусы WB. `localStorage` хранит лишь UI-настройки магазина и вкладки.

## «На сборке»
- Родители формируются из всех открытых WB-поставок, поэтому пустая поставка тоже видна.
- Заказы связываются по `supply_id`; отсутствующая связь попадает в «Без поставки».
- Перенос заказа доступен в существующую или новую поставку; исходная поставка исключается из списка назначения.
- Печать WB-стикеров выполняется пакетами максимум 100 заказов.
- Массовая нижняя панель содержит печать, перенос, лист подбора и сброс выбора. Передачи отдельных заказов в доставку нет.

## Передача в доставку
- Действие доступно только на родителе поставки.
- Сначала вызывается официальный `PATCH /api/v3/supplies/{supplyId}/deliver`.
- Затем обновляются связанные WMS-остатки и запускается полный sync; вкладка определяется новым статусом WB, а не локальной подстановкой.

## Данные товара
- FBS WB order — источник `order id`, `nmId`, `chrtId`, `skus`.
- Баркод берётся из `skus` конкретного заказа.
- `products` по `store_id + nm_id` даёт фото, название, бренд и артикул продавца.
- Размер ищется в `products.sizes` по точному SKU и `chrtId`; случайный размер не подставляется.
- Нет точного варианта — UI показывает «Размер не определён» и предлагает синхронизацию товаров.
