# ELESTET

ELESTET — операционная SaaS-система для продавцов Wildberries, фулфилмент-команд и складских операторов.

Проект объединяет работу с заказами FBS, товарными партиями, коробами, адресным хранением, логистикой, маркировкой и внутренними процессами компании. Интерфейс ориентирован на ежедневную работу: компактные таблицы, сканирование штрихкодов и QR, печать этикеток, Excel/PDF-выгрузки и разграничение доступа сотрудников.

## Основные возможности

- **FBS:** синхронизация заказов и поставок Wildberries, официальные статусы, сборка, перенос заказов, печать стикеров, сканирование КИЗ и управление остатками.
- **Фулфилмент:** приёмка, ОТК, упаковка, маркировка, формирование коробов и передача поставок в логистику.
- **WMS:** склады, стеллажи, паллетоместа, QR-адресация коробов, перемещения, поиск, история и инвентаризация.
- **Логистика:** рейсы, поставки, статусы, даты, перевозчики, склады назначения, накладные и стикеры WB.
- **Товары и магазины:** каталог товаров, размеры и баркоды, себестоимость, API-подключения магазинов и Excel-выгрузки.
- **Стикеры и маркировка:** собственные шаблоны, импорт данных WB, наборы стикеров, PDF-печать и интеграция с Teksher.
- **Отзывы и реклама WB:** синхронизация отзывов, шаблоны и автоматизация ответов, управление рекламными кампаниями.
- **Счета и тарифы:** расчёт услуг фулфилмента, логистики и расходников, подписки и контроль доступа по тарифу.
- **Команды:** несколько компаний у пользователя, роли сотрудников, детальные разрешения и B2B-аутсорс этапов.

## Архитектура

- Frontend: React, TypeScript, Vite.
- Стили: Tailwind CSS.
- Навигация: React Router.
- Backend: Supabase Auth, Postgres, RLS, RPC, Storage и Edge Functions.
- Интеграции: Wildberries API, Teksher и платёжная инфраструктура.
- Документы: jsPDF, SheetJS, JSZip, QR- и barcode-библиотеки.

Компания (`account`) является границей данных в multi-tenant модели. Пользователь может состоять в нескольких компаниях. Доступ к данным защищается серверными политиками Supabase RLS и проверками в RPC/Edge Functions.

## Требования

- Node.js 20 или новее.
- npm.
- Проект Supabase с подготовленной схемой, политиками и Edge Functions.

## Локальный запуск

1. Установите зависимости:

```bash
npm install
```

2. Создайте `.env` на основе `.env.example`:

```env
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key
```

3. Запустите development-сервер:

```bash
npm run dev
```

Привилегированные ключи Supabase, API-ключи магазинов и другие секреты нельзя добавлять во frontend-переменные или отслеживаемые Git-файлы.

## Проверка и сборка

```bash
npx tsc -b --pretty false
npm run build
npm run preview
```

Production-сборка создаётся в каталоге `dist/`.

## Структура проекта

```text
src/
  components/   UI и составные компоненты
  hooks/        авторизация, компании, роли и данные приложения
  lib/          общие утилиты, генераторы PDF/Excel/QR и конфигурация
  pages/        страницы приложения
  services/     доступ к Supabase и бизнес-операции
  types/        доменные TypeScript-типы

supabase/
  functions/    Supabase Edge Functions
  *.sql         схема и SQL-патчи проекта

memory-bank/
  components/   документация отдельных подсистем
  *.md          контекст, архитектурные правила и прогресс разработки
```

Основная композиция приложения и контроль страниц находятся в `src/App.tsx`. Клиент Supabase создаётся в `src/lib/supabase.ts`.

## Документация проекта

Актуальные технические решения и рабочий контекст хранятся в `memory-bank/`:

- `projectbrief.md` — назначение и границы продукта;
- `productContext.md` — продуктовая модель и пользовательские сценарии;
- `systemPatterns.md` — архитектурные и бизнес-инварианты;
- `techContext.md` — стек, инфраструктура и технический контекст;
- `activeContext.md` — последнее состояние разработки;
- `progress.md` — история выполненной работы;
- `components/` — подробности FBS, WMS, ролей, поставок и других подсистем.

Перед изменением сложной бизнес-логики необходимо сверяться с актуальным кодом и соответствующим документом Memory Bank.

## Разработка

- Изменения должны быть минимальными и соответствовать поставленной задаче.
- Нельзя менять соседнюю бизнес-логику или UX без необходимости.
- Для новых операций с данными необходимо сохранять tenant-изоляцию и серверную проверку прав.
- После изменений следует запускать TypeScript-проверку и production-сборку.
- Секреты и реальные учётные данные не должны попадать в Git, README или Memory Bank.

## Развёртывание

Frontend развёртывается на Vercel как SPA. Ветка production — `main`; маршруты перенаправляются на `index.html` через `vercel.json`.

Backend работает в Supabase. SQL-патчи и Edge Functions следует применять только после проверки их актуальности и зависимостей; старые патчи нельзя запускать вслепую как единый установочный список.
